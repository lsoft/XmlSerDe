# Цена формы вызова: virtual против невиртуального

Замер, которым принято решение в [sink-contract.md](sink-contract.md): чего стоит заменить интерфейсы `IExhauster`/`IInjector` абстрактными базами с `virtual`-методами.

## 1. Почему вопрос вообще возник

Генератор пишет вызов стока **по конкретному типу**, а не по интерфейсу:

```csharp
public static void Serialize(MyExhauster exh, Node obj, bool appendXmlHead)
{
    exh.Append("<Node>");
    ...
}
```

Пока методы стока невиртуальные, это прямой `call`, и тело инлайнится. Если они станут `virtual`, вызов девиртуализуется только тогда, когда JIT знает точный тип. Отсюда и весь вопрос: сколько стоит та часть случаев, где он его не знает.

## 2. Как устроен замер

`DispatchMatrixFixture` (BenchmarkDotNet, ключ `--dispatch-cost`), экзостеры и хосты — в `XmlSerDe.Tests/Dispatch`. Формы различаются ровно тем, что JIT знает о типе на сгенерированном сайте; тела посимвольно одинаковы.

Семей две, и одна без другой врёт:

- **thin** — тело вырождено в одно сложение. Верхняя оценка: чем дешевле тело, тем большую долю занимает вызов.
- **fat** — тело то же, что у настоящего `StringBuilderExhauster`. Оценка для живого кода.

Документ — `XmlObject2`, восемь вызовов экзостера. В каждой группе есть **контроль**: копия первого случая слово в слово. Разницу между формами читать имеет смысл только если она больше разброса между базой и контролем.

### Чего в замере нет

Отдельного микро-замера «один `Append(int)` в цикле». Он был и врал: тело складывает в поле, вызовы идут подряд, и цикл упирается в цепочку `load-add-store` по одному адресу — 1.6 нс на итерацию, латентность store-forwarding, а не вызов. Полиморфный случай выходил там **вдвое быстрее** прямого просто потому, что аккумулятора у него два и цепочка расщепляется.

До BDN этот замер был самодельной пробой по образцу `FeatureCostProbe`. Она тоже врала: контрольный случай расходился с базой на 13% — шум оказался больше измеряемого эффекта. Отсюда BenchmarkDotNet.

## 3. Числа

Сняты до перевода контракта на базовые классы, поэтому в таблицах есть строка «невиртуальный» — форма, которой после перехода уже нет. Именно ради этой строки замер и делался.

Нс на документ (у полиморфной строки в сыром отчёте два документа за итерацию, здесь поделено).

### net10.0

| форма | thin | ×base | fat | ×base |
|---|---:|---:|---:|---:|
| невиртуальный (было) | 0.809 | 1.00 | 9.40 | 1.00 |
| невиртуальный (**контроль**) | 0.776 | 0.96 | 9.28 | 0.99 |
| virtual, наследник sealed | 0.825 | 1.02 | 9.32 | 0.99 |
| **virtual, sealed + свой `override`** | 0.819 | **1.02** | 9.33 | **1.00** |
| virtual, наследник открыт | 4.134 | 5.1 | 9.71 | 1.04 |
| virtual, сайт полиморфен | 4.82 | 5.9 | 14.43 | 1.54 |

### net472 (нет динамического PGO)

| форма | thin | ×base | fat | ×base |
|---|---:|---:|---:|---:|
| невиртуальный (было) | 3.546 | 1.00 | 113.5 | 1.00 |
| невиртуальный (**контроль**) | 3.530 | 1.00 | 116.1 | 1.02 |
| virtual, наследник sealed | 3.599 | 1.02 | 112.7 | 0.99 |
| **virtual, sealed + свой `override`** | 3.519 | **1.01** | 116.4 | **1.01** |
| virtual, наследник открыт | 11.09 | 3.13 | 115.8 | 1.02 |
| virtual, сайт полиморфен | 11.50 | 3.24 | 117.1 | 1.03 |

Оговорка по надёжности: группа thin на net472 гуляет между прогонами (в одном из них базовый случай показал 6.07 при своём же контроле 3.48). Опорой берётся контроль — он воспроизводится. Группа fat стабильна.

## 4. Что из этого следует

**Запечатанный наследник бесплатен.** 0.99–1.02× при шуме 0.5–6%, на обеих платформах и на обоих телах. Собственный `override` ничего не меняет: важен только `sealed` на том типе, который назван в атрибуте. Работает и на net472, значит держится на статической девиртуализации по `sealed`, а не на динамическом PGO.

**Незапечатанный лист платит ровно за потерянный инлайн — и ровно столько, сколько инлайнилось.** На настоящем теле это +4% (net10.0) и в пределах шума (net472). Пугающие ×5.1 и ×3.1 — это thin, тело в одну инструкцию, которого в жизни не бывает: там прямой вызов сворачивался в несколько сложений, и терять было чему.

**Дорогая клетка одна — полиморфный сайт:** 1.54× на настоящем теле (net10.0), то есть около +0.9 нс на вызов. Сам собой он не возникает: генератор пишет вызов по зарегистрированному типу, и чтобы через один хост пошли два разных наследника, это нужно сделать нарочно.

**Вывод для дизайна:** переход на базовые классы стоит ноль при правиле «зарегистрированный тип запечатан», и это правило генератор проверяет сам — `XMLSERDE010`.

## 5. Чего замер не покрывает

- Сторону `IInjector`: механизм тот же, числа могут отличаться.
- Документы с другим соотношением «вызовов экзостера на единицу прочей работы».
- net8.0.

## 6. Как повторить

```bash
dotnet run --project XmlSerDe.PerformanceTests -c Release -f net10.0 -- --dispatch-cost
```

Для net472 — собрать под этот таргет и запустить `XmlSerDe.PerformanceTests.exe --dispatch-cost` из `bin\Release\net472`.

Текущая фикстура строки «невиртуальный» уже не содержит: `ExhausterBase` объявляет члены `abstract`, и реализация обязана быть `override`. Базой в ней служит запечатанный наследник — то есть та самая форма, которая по таблицам выше от невиртуальной неотличима.
