# Оптимизации по итогам ревью 2026-09-10

**Статус:** сделано 2026-09-10. Замеры сняты временной пробой `--review-cost`
(клон `FeatureCostProbe`: привязка к ядру, прогрев, лучший из семи раундов), проба
после замера удалена. Числа — net10.0, нс на операцию.

## Что изменилось

| Место | Было | Стало |
|---|---|---|
| `XmlTextEncoder` | посимвольный переключатель на каждый символ строки | векторный поиск первого кодируемого (`SearchValues` по Latin-1 + `IndexOfAnyInRange` по суррогатам), дальше сегментами; после попадания — скалярное окно в 8 символов, потому что кодируемые символы ходят кучно |
| `XmlAttributeEncoder` | посимвольный `WriteSlice(value, i, 1)` после первого экранируемого | пакеты между экранируемыми, поиск `SearchValues` по семи символам; заодно перестал рвать суррогатную пару на UTF-8 стоке |
| `LengthEstimatorExhauster.AppendEncoded` | «+4 за спецсимвол», не знал `&quot;`, 160..255 и суррогаты — второй проход рос с копированием | точная надбавка `XmlTextEncoder.EncodedOverhead`: векторный поиск первого попадания, дальше табличный подсчёт |
| `Utf8BinaryExhauster` | `GetByteCount` + `GetBytes` на каждый срез; числа через UTF-16 и перекодирование | срез до 256 символов — один `GetBytes`; числа, даты, Guid — `IUtf8SpanFormattable` сразу в байты; `TimeSpan` — `Ascii.FromUtf16` |
| `XmlNumberLexis.TryFormat(TimeSpan)` | `DurationCharCount` + `WriteDuration`, деления дважды | при буфере от 27 символов — сразу `WriteDuration` |
| `Utf8StreamExhauster` | открытый класс, сгенерированный вызов не девиртуализуется | `sealed` |
| `XmlScan.HeadHasAttributes` | `<Foo />` с пробелом считался головой с атрибутами | пробелы между именем и `>` не считаются |
| строковый `[XmlAttribute]` при двух и более атрибутных членах | `DecodeAttributeValue(...).ToString()` — две строки на значение со ссылкой | `DecodeAttributeValueToString` — одна |
| `XmlSerializer.BuildXmlDeclaration` (compat) | конкатенация на каждый вызов | константы для utf-8 и utf-16 |

## Что не окупилось и почему оставлено

Плотный кодируемый текст — спецсимвол через два-три знака, эмодзи через два знака —
стал на 10–20 % медленнее на UTF-16 стоках: сегмент из двух символов пишется одним
`Append(string, start, 2)`, а раньше двумя `Append(char)`, и вызов дороже. Латиница
подряд — без изменений. Такой плотности в данных почти не бывает, а на обычном тексте
выигрыш 40 %.

Точная оценка длины на неанглийском тексте стоит дороже, чем стоил рост буфера с
копированием (+10 % на латинице, +30 % на эмодзи в двухпроходной схеме). Оставлена
точной намеренно: рост буфера на больших документах — это вторая аренда размером с
документ, часто в LOH, а оценщик существует ровно затем, чтобы её не было. На ASCII
оценка по-прежнему один векторный проход.

`DateTime` в байты через `IUtf8SpanFormattable` не быстрее, чем через `char` +
перекодирование: формат с `FFFFFFFK` дорог сам по себе.

## Что из перф-списка ревью не делалось

Время работы генератора (`TryGetBuiltin` пересобирает таблицу, `IsList`/`IsArray`
конструируют символы) и детерминизм алиаса из `GetHashCode` — это сборка, а не
рантайм; повторный разбор головы корня в compat `Deserialize` и инлайн первого
`Rent` в `PooledArrayBuilder.Add` — единицы наносекунд на документ.
